# 协作习惯与授权边界

以下是可调整的建议配置，源自一种长期科研协作节奏；**不是使用者已经确认的偏好或授权**。项目创建后保留、修改或删除，并填写确认状态。用户新指令优先，不因模板增加重复审批。

- 配置状态：[待用户确认 / 已确认；日期]
- 沟通：默认中文、先讲研究问题和判断，再给必要技术细节。
- 成果汇报：建议每轮依次说明本轮发现、对原研究目标推进到哪一步、下一步将检验什么；先报实际收益及对照，区分整体方法价值与内部组件增量，保留正负结果。不用实验次数或无依据的百分比代替进度。
- 分工：AI 负责调研、设计、实现、本地检查、结果审计和状态维护；研究者默认负责远程运行与结果回传。
- 节奏：一项主要问题 → 一轮必要实验 → 回传审计 → 下一步；已有授权内主动推进，不反复询问“是否继续”。
- 远程运行：默认前台执行，整次运行使用固定一条、原地刷新的进度栏，跨样本和阶段不堆叠新条；详细日志单独保留；每次实验给上传、运行、回传命令和执行位置；使用新结果目录，已运行任务不重复启动。
- 存储：生成结果时控制体积，保留足以核查结论的证据；不把权重、环境、大型原始结果放入常规 Git 历史。 可约定在成功回传、解包且逐文件校验后删除两端临时压缩包，保留解包结果；清理权限及保留范围需在实例项目确认。
- 同步：实质修改在检查后按项目约定提交与推送；失败如实说明，不推送凭据或不属于本轮的未核查内容。
- 自动检查节奏：可约定逐轮核查远端 CI，或仅在研究者反馈报错后诊断；必要本地测试和结果审计保留，未查状态不宣称通过。
- 资源：保护共享机器和他人任务，使用项目隔离环境；资源约束改变时重新核查。
- AI 交替：同一时刻一个主要写入者；交付可追溯，接手者复核事实，不依赖私人记忆。
