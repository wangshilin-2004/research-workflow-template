# 每日工作节奏

## 边界验证之后转向结构改进

改变工作负载尺度仍保留主要矛盾时，结束该解释分支，回到动作可达性、成本模型或执行结构；不要无限增加长度或容量。保留已经有效的组件和资源收益，净时延尚无改善也应明确记录。

分层控制可以先选完整动作目标，再在目标内作局部投入。历史嵌套结果不等于独立执行该动作的反事实结果；未执行动作的成本外推必须标记。完整周期代价乘预计剩余次数只是稳定工作量代理；没有未来状态转移、回报或rollout时，不称多轮规划或强化学习。

在旧策略访问历史上重算新动作，只验证选择可变化，不能推断新轨迹的速度。整合机制与旧控制保持同执行组件和校准条件，在线计入规划、额外计算与等待，再决定是否进入下一系统组件。

## 先把“请求更大”拆成可检验变量

当研究者提出输入、样本或任务可能太小时，先核查实际长度、是否被上限截断、自然终止比例、校准占比与有效自主阶段；用证据评价提议，不默认同意，也不为坚持原计划而忽略实验条件。

输入长度、输出长度、独立内容数量、并发与到达模式是不同变量。优先保持执行容量和算法不变，只改变一个主要条件；容量必须一起改变时明确额外因素。保留自然终止，不能为制造长任务强行补输出。校准后统计用于解释，完整部署成本不扣除。

在线动作接口存在不代表动作真正进入过比较；区分未达到可选状态、预测后主动放弃、执行被限制。后验可达性只提供机制线索，不能直接当新策略收益。新假设改变下一步时，将原机制想法标为待验证，避免交接误报已实现。

## 容量边界与决策精度分别验证

动作真实被使用却没有净收益时，先区分资源上限限制与控制估计失准。用少量同组件固定容量参照和完整自适应方案判断空间，不自动增加阈值或逐档扫描。固定组保持固定，动态组的校准成本必须保留；同硬件组件不意味着控制协议相同，结论按完整方法解释。

计算节点下降但调用、往返或等待增加时，报告完整成本，避免把资源代理当加速。失败实验中的结构事实与正式性能胜负分别记录，已有独立通过的成果继续保留。

独立参考可在同一确定模型/后端内按完整输入身份去重，仍逐项核验所有输出。跨进程复用需保存原预测、输入与模型条件的绑定，说明未新运行参考。仅在不破坏其他检查的前提下继续收集失败证据，最终状态不变；不因每次局部分歧都重启一轮昂贵诊断。

## 部分实验失败时保留可验证的结论

先用独立参考和原件绑定定位失败，保留全场失败状态。若要报告其中有效对照，明确列出覆盖/排除场景，对所选场景完整重放原检查；不得只删异常样本、覆盖原状态或把局部通过写成全局通过。数值近似、不同执行历史与实际数据错误区分，不能以差异很小自动放宽标准。

新控制动作整合到执行后，参照也应匹配硬件注册、初始化与校准协议；协议改变要明说，所有成本保留。把预算、预测与共享代价一次接通，用少量必要的完整对照判断系统收益，再做结构取舍；不必每个模块独自胜出才推进。

## 扩展动作空间时加快有效推进

研究者指出控制档位过粗时，先核对实际执行范围与收益预测的限制；用已有正确性通过的轨迹检查中间动作机会，区分后验可裁剪资源与真正能在线省去的工作。论文方法、公开代码和已复现结果分别标注。

算法的逻辑动作与硬件执行形状分开设计；较细动作可能增加填充、拆批和决策开销，按完整实际执行计费。测量新规划器本身的开销，不能只比较动作数量。已有服务器任务继续运行时，可先准备隔离的模块和测试，但不把尚未接入的功能报为在线实现；下一次整合必要机制一起验证，不每加一档就展开一轮实验。

## 有效结果后出现局部正确性分歧

- 区分生成完成、结构检查、独立参考和性能结论。诊断完成不等于失败的源实验已通过。
- 保留此前独立验证的成果；冻结方法，用现有原件做最小有信息价值的诊断，不换测试内容或先放宽容差。
- 完全相同输入前缀可去重执行独立参考；不同前缀分别检查，不能用多数输出代替参考。保留输入身份与简洁可复核预测。
- 历史回放若更早状态已偏离，立即停止该路径；不强行注入已知答案继续。记录回放未复现的并发、缓存与调度环境。
- 报告方法组件的已实现、已验证及未完成部分。实验次数不代表完成比例；局部排障结束后回到主线，不无限追加诊断。

## 开始：从证据出发

先看 STATUS、最近一次 DELIVERIES、实际版本与新增结果。确认是否已有任务在运行、结果是否完整、是否有人留下未提交修改。先审计再决定；不要收到“已回传”就自动重跑。

向研究者用简短中文说明：**当前卡在哪、这一轮要判断什么、为什么这个判断影响研究主线。** 技术细节留在实验卡，便于追查。

## 一轮：研究者运行，AI 负责准备与审计

1. **设计**：写清假设、最简单替代解释、对照、主要指标与正确性约束。预先说明正、负、不确定三种结果各如何改变下一步。
2. **准备**：修改必要代码，完成与改动相称的本地检查；明确哪些真实设备检查尚未执行。配置、版本和结果目录可追溯。
3. **交付运行**：提供本地上传、远程运行、本地回传三组命令，明确执行位置和路径。每轮使用独立结果名，不覆盖旧结果；预计规模或时长没有依据时直接写未知。
4. **等待回传**：记录等待哪次实验、输出位置及作业归属。默认前台执行，整次运行共用一条原地刷新的进度栏，跨样本与阶段不刷出多行；详细日志独立保存；不擅自转为后台任务。不重复启动已经运行的实验。
5. **审计**：先检查完整性、错误、配置、输出长度/正确性与计量口径，再看性能。区分真实测量、模拟和代理量；保存原始证据与分析入口。
6. **决策**：继续、修正、缩小范围、暂停或进入确认。更新 STATUS，追加有用的 EVIDENCE、DECISIONS、DELIVERIES；按项目约定提交、推送，并如实报告状态。

若用户另有分工，按 PREFERENCES 执行。例如 AI 获准运行实验后可自行执行，流程仍保留相同的证据和资源边界。

## 显示维护也要验证实际体验

“有回车字符”不等于用户看到的是单条进度。涉及子进程时检查管道缓冲、日志混排、阶段结束换行与窄终端折行。可以用不加载模型的端到端预览验证显示，避免为界面修复重跑昂贵实验。非交互输出采用简洁状态记录，不堆积动画帧。

## 本地、自动检查与真实实验分别核验

新增测试依赖或外部源码时，同步维护自动检查环境的版本和目录布局。用干净检出确认测试不依赖研究者机器上偶然存在的包或未跟踪文件；推送后核对实际运行结果，不能把“本地通过”或“已推送”写成“自动检查通过”。交付中分别说明本地、自动检查、真实设备实验的状态，以及有理由跳过的测试。

不同平台可能对未承诺稳定顺序的操作给出不同合法排列。测试应按逻辑身份和真实前置条件构造状态，用替代排列验证；不能为修测试而放松运行时的安全检查。合成动作测试与真实选择质量测试分开，修好自动检查不等于完成研究正确性或性能验证。

## 控制成本

先做有区分力的小实验；形成候选后才冻结配置做独立验证。小样本用于找异常与判断是否值得继续，不能直接承诺普适效果。重复次数取决于波动与目标差异，不固定要求每次重复四次或跑完整基准。

有限诊断到达事前停止条件后，保留未解边界与原失败状态，回到仍可独立验证的主线问题。若改用记录/回放来隔离共享资源影响，先验证完整输入/响应与状态匹配；条件回放不能替代真实在线性能或修复原正确性缺口。

结果在生成时就控制体积：默认保留配置、汇总、错误、必要的逐样本记录；诊断需要完整 trace 时显式开启。压缩不等于删除；删减数据前确认仍能重建核心结论。权重、环境和大体积结果不进入常规 Git 历史。

共享机器先确认本次新增资源需求和作业归属，使用项目隔离环境；不停止他人服务、不修改公共环境。无需每轮重复检查没有变化且不影响决策的事项。

## 每轮回复保持可执行

- 这轮发现了什么，能说明什么、不能说明什么。
- 原研究问题是什么，本轮推进了哪一层；哪些已实现、哪些已验证、哪些仍是假设，避免局部组件优化悄悄替代总目标。
- 做了哪些修改，实际通过哪些检查，未验证什么。
- 下一步唯一优先动作；需要用户运行时给准确命令和输出位置。
- 当前提交/推送状态；如失败说明实际原因。

没有代码改动且不需要新实验时，不为凑流程生成同步命令。短咨询不强制产生交付文件。

## 阶段复盘与汇报

完成主要候选、发生转向或 AI 接手时，看 RESEARCH_REVIEW。每周或向导师汇报前，用“研究目标 → 已得到的证据 → 当前判断及局限 → 下周一个主要问题”组织汇报。任务完成数量不是贡献；先解决主张缺口，再扩充实验规模。
