# 每轮研究

1. 先读当前状态与长期习惯，核对是否有新产物或在跑的任务。
2. 只选一个会改变下一步的问题。已有证据足够时直接更新判断；需要实验时，写清对照、观察终点和停止条件。
3. 按分工把本地分析、实现与检查做完。交给研究者运行时，附输入、运行与回传命令、预计时长。
4. 回传核实后，说清实际收益或阴性发现、适用边界、下一步。更新一处状态，引用一处证据。独立题目、重复测量和条件模拟分别标明。

阶段收敛时，分别判断“是否实现”“在什么对照下有效”“能否支撑研究贡献”。连续局部试验没有改善整体取舍，就执行停止条件，冻结现有版本，用一次有结束标准的强基线和简单方法对照决定采用、简化或停止。不要用实验数量替代研究进展，也不要把移除基线开销的全部收益归给新方法。

做系统归因时分开核查事件数量、单次代价和累计时间；不能把“调用更多”直接写成“主要瓶颈”。离线轨迹里的事后机会，必须区分当时已可见的信息与后来发生的事件；变更调度会改变后续轨迹，不能把静态配对数换算为实测加速。

跨层收益用同一份内容分别核查：上层数据变小，先看下层实际交付量，再看用户等待；不用换算百分比代替测量。服务发出回复后还可能占用共享资源，单独记录“已回复”和“能做下一项”的时刻，区分当前用户与排队用户可能得到的收益。

若要判断收尾工作会不会拖住下一位使用者，把资源占用区间与其他使用者已就绪的等待区间取交集；同一时刻的多名等待者，计算共享资源时间时只算一次。先确认这种机会确实存在，再用实际完成时间检验收益。

平均等待、单项平均完成时间和整组最后完成时间可能给出不同答案。若次要指标稳定获益而主指标未过线，记下适合的目标和使用条件，按原规则决定默认配置；下一步可用留出输入直接检验冻结后的整体方案。
