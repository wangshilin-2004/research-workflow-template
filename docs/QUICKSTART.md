# 十分钟开始

## 1. 先决定模板放在哪里

本仓库是通用工具和空白模板，具体课题放在另一个项目里。可以下载本仓库，也可以在 GitHub 点击 Use this template 保留自己的工作流副本。两者都不会自动创建具体课题或配置远程机器。

已有课题使用初始化工具时，目标路径指向课题根目录；新课题先自行创建目录。Python 3.9 或更新版本即可，不需要安装第三方库。

```bash
# 在工作流模板仓库目录运行；将路径替换为真实课题目录。
python3 tools/init_project.py --project /path/to/your-project
```

如果已经有 `research/` 记录，不要删除后重新初始化；按 [升级指南](EVOLUTION.md) 合并。工具会拒绝同名文件冲突。

## 2. 只先填三份记录

- `research/BRIEF.md`：谁遇到了什么问题，最终要改善什么，哪些性质不能损失。
- `research/PREFERENCES.md`：确认或调整建议分工、运行方式、同步和权限。不要把模板默认值当作已获得授权。
- `research/STATUS.md`：现在在哪里、已有何种证据、下一项具体动作、还不知道什么。

其他表格先保持空白。一次口头解释不需要一张实验卡；一次影响科研判断的实验需要。

## 3. 让 AI 从同一个入口接手

给项目已有的 AGENTS.md、其他 AI 规则文件或开场消息补充：

> 先读 research/START_HERE.md。当前任务以 research/STATUS.md 为准；核实版本、结果及正在运行的任务，再在用户已授权范围内推进。没有结果不能声称复核过。

不要覆盖项目既有约束。先让接手 AI 简短复述目标、证据、下一步与未知，再开始实质工作。无需为了流程重新批准已经明确授权的工作。

## 4. 开始第一轮

按 [每日节奏](DAILY_WORK.md) 选择最值得减少的一项不确定性，先确认现有证据是否足够，必要时设计实验。使用 [示例](../examples/one-research-cycle.md) 判断记录粒度。

若没有代码或算力，第一轮可以是近邻机制核查或可复现性检查，不必强行跑实验。不要把尚未执行的计划写成结果。
