# AI 交替与信息对齐

默认一次一个主要写入者。交替接手比并行修改更容易审计；确有需要再划分并行任务、分支和整合负责人。

## 能访问项目的 AI

复制这段作为接手消息：

> 请阅读 research/START_HERE.md 和最新 STATUS、DELIVERIES。先核对 Git 版本、未提交修改、结果文件及正在运行的任务，简短复述研究目标、已知证据、当前优先动作与不能声称的结论。接着在我已授权范围内推进；不重跑已完成实验，不把历史计划当当前任务。缺少关键文件或权限时准确说明，其他可独立推进的工作继续完成。

## 只能聊天的 AI

在模板仓库目录生成新文件：

```bash
python3 tools/export_handoff.py --project /path/to/your-project --output /path/to/handoff-002.md
```

人工检查后传递，并附上：

> 这是某一时刻的研究快照，代码和原始结果未包含。请区分你实际核查的内容与摘要转述；输出带依据、局限、建议修改和待验证问题的建议交付，不声称已经运行、改动或推送。需要哪一份证据请准确列出，不依赖前一个 AI 的记忆。

交接包不是脱敏工具，也不是权限凭证。原始文件内的相对路径需要原项目才能解析。缺少数据时可以评审设计，但不能冒充结果复核。

## 结果复核提示词

> 先读本轮实验卡和原始输出，再核对配置、实现版本、正确性、计时范围、单位与对照。把观察、解释和创新性判断分开。先报告会改变下一步的重要问题；没有新问题时不要制造任务。给出当前证据支持范围及最小下一步。

## 收尾与下一任核查

> 请把本轮真实完成的内容、实际检查、产物路径、版本、未完事项和运行中的任务记录到 DELIVERIES；更新唯一当前 STATUS。新事实登记 EVIDENCE，重要选择登记 DECISIONS。不把计划写成完成，不把自检写成独立审计，按项目约定同步。

下一任核查原始证据后才能将“交付者自检”改为“接手者复核”。两个 AI 的结论冲突时比较来源、版本和口径，不按回答时间或措辞自信程度决定。核查未完成就保留未知，不直接覆盖对方工作。

## 防止交接负担膨胀

STATUS 保持短，历史留在决策与交付记录。默认先读当前材料，按问题追溯历史。超长项目可按阶段归档，并在索引中保留来源链接；导出器不会递归打包索引链接指向的代码、实验卡或归档，接手者需要时补充具体文件。
